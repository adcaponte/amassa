# Phase 4 — UI Design Contract: Contador de Queima

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **no new design system** — `components.json` already exists (initialized in
Phase 2b), the AMASSA token set is already mapped into `@theme`/`@theme inline` in
`app/globals.css`, and shared shell components (`EstadoVazio`, `EstadoErro`, `CabecalhoPagina`,
`CartaoPainel`) already exist in `components/amassa/`. **The shadcn gate does not apply** — this
document inherits the established system and adds only what is new for Fornos: the medidor
component, the dois-toques flow, the "Desfazer" toast, and the Recharts reports.

## Spacing Scale

Inherited from the project-wide 8-point scale (`04-DESIGN-SYSTEM.md`, applied since Phase 2b).
No new tokens this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, medidor tick spacing at small sizes |
| sm | 8px | Compact element spacing (rodapé do cartão, selo + texto) |
| md | 16px | Default element spacing, gap between stacked cartões on mobile |
| lg | 24px | Section padding (página do forno sections) |
| xl | 32px | Layout gaps between banner and cartões grid |
| 2xl | 48px | Major section breaks (relatórios: estatísticas block → gráficos block) |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Touch targets minimum **44px** — applies to every icon-only control (ex.: "Desfazer" ação dentro
  do toast, ⋮ menu na página do forno) and to the "Queimar" button, which on mobile is
  **full-width** and at least 44px tall (`04-DESIGN-SYSTEM.md` §6, `min-h-[44px]` pattern already
  used in `EstadoVazio`).
- Form fields never below 16px (`text-corpo`) — no form exists in the dois-toques flow itself
  (deliberately, D-04/§8), but the maintenance dialog (responsável, observações) and the forno
  edit fields on the forno page do have inputs and must use `text-corpo`.
- Medidor entalhes (tick marks every 10 queimas) are a visual notch pattern, not a spacing token —
  their spacing is derived from `limite / 10`, not from the 8-point scale.

## Typography

Inherited verbatim from `app/globals.css` (established Phase 2b, do not re-declare or invent new
sizes/weights this phase).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (`text-display`) | 28px | 700 | 32px (1.14) |
| Heading (`text-titulo`) | 20px | 600 | 28px (1.4) |
| Body (`text-corpo`) | 16px | 400 | 24px (1.5) |
| Label/apoio (`text-apoio`) | 14px | 400 | 20px (1.43) |
| Micro (`text-micro`) | 12px | 500, letter-spacing 0.06em | 16px (1.33) |
| Mono (`text-mono`) | 13px | 400 | 18px (1.38) |

Fornos-specific typography usage:
- **Contador `atual / limite`** on the cartão and detail page uses `text-mono` (tabular figures,
  per `04-DESIGN-SYSTEM.md` §8) — never `text-corpo`, so digits align as the counter changes.
- **Medidor labels** (`0 / atenção N / limite N`) use `text-micro` under the bar.
- **Selo textual** ("Manutenção próxima" / "Manutenção vencida") uses `text-apoio` with the
  matching `--color-forno-atencao-texto`/`--color-forno-critico-texto` foreground.
- **Rodapé do cartão** ("Última manutenção em {data} · {responsável} · {total} no total") uses
  `text-apoio` `text-muted-foreground`, same as `EstadoVazio`/`EstadoErro` body convention.
- **Banner agregado** heading uses `text-corpo` weight via inline `font-medium`/`text-apoio` — see
  Copywriting Contract row below for exact string; no new type role needed.

## Color

Inherited verbatim from `app/globals.css` `@theme`/`@theme inline` (Phase 2b). No new dominant/
secondary/accent tokens this phase — only the already-declared, **NÃO ALTERAR** Fornos-specific
semantic tokens are newly *used* here.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-fundo` `#F6F3F0` | Page background |
| Secondary (30%) | `--color-superficie` `#FFFFFF` (cards) / `--color-superficie-2` `#EFEAE5` | Cartões dos fornos, banner container, relatório cards |
| Accent (10%) | `--color-acento` `#894025` (terracota) | Reserved for: the **"Queimar"** button on every cartão (the single most-used primary action in the system), **"Registrar manutenção"** and **"Novo forno"** primary buttons, focus ring (`--color-ring`), active state of the top seletor (Fornos/Relatórios). **Never** more than one terracota button per screen (`04-DESIGN-SYSTEM.md` §3) — the cartão's "Queimar" is the terracota button on `/queimas`; the forno detail page's "Registrar manutenção" is the terracota button on `/queimas/[id]`. |
| Destructive | `--color-erro` `#B91C1C` (mapped to shadcn `--color-destructive`) | Reserved for: the **"Excluir"** confirm button inside the queima-deletion `AlertDialog` (FOR-10) only. Not used for desativar/reativar forno (reversible, not deletion — no destructive styling). |

**Fornos-specific semantic tokens (already declared, `NÃO ALTERAR` — do not redefine or recolor
this phase):**

| Token | Value | Usage |
|-------|-------|-------|
| `--color-forno-ok` | `#D97706` | Medidor bar fill when `atual < limite − 10` |
| `--color-forno-atencao` / `-fundo` / `-texto` | `#CA8A04` / `#FEF9C3` / `#854D0E` | Medidor bar, selo "Manutenção próxima", banner row, cartão in-attention styling |
| `--color-forno-critico` / `-fundo` / `-texto` | `#DC2626` / `#FEE2E2` / `#991B1B` | Medidor bar, selo "Manutenção vencida", banner row, cartão in-critical styling — **pair with an alert icon** (`04-DESIGN-SYSTEM.md` §3 conflict note 1: this red means real urgency, unlike the unrelated "turma excedida" red in Agenda, which must never carry an alert icon) |
| `--color-biscoito` | `#9A3412` | Tipo de queima "biscoito" — cartão selector, história, chart series. Only inside the Fornos module and its charts, never decorative. |
| `--color-esmalte` | `#155E75` | Tipo de queima "esmalte" — same scope as above |
| `--color-ouro` | `#CA8A04` | Tipo de queima "ouro" — same scope as above. **Same hex as `--color-forno-atencao`** — disambiguated by context only (ouro appears exclusively as a stacked-bar chart segment with a legend; atenção appears exclusively in medidor/selo/banner). **Never place a nível selo inside a chart** — that is what keeps the two unambiguous (`04-DESIGN-SYSTEM.md` §3 conflict note 2). |

Accent reserved for (explicit, restated): "Queimar" button, "Registrar manutenção" button, "Novo
forno" button, focus ring, active seletor tab indicator. Never for decorative fills, never for the
medidor bar (which uses the forno-level tokens, not accent), never for the chart series (which use
the tipo-de-queima tokens).

## Copywriting Contract

Voice: `04-DESIGN-SYSTEM.md` §9 — affective but sober for the gestor-facing tool, never
corporate, always says what to do. New strings below extend the pattern already codified in
`lib/encomendas/textos.ts` (e.g. `FRASE_ERRO_TITULO = "Algo não funcionou."`,
`FRASE_FALHA_AO_SALVAR = "Não deu para salvar. Verifique a internet e tente de novo."`) — the
planner should add an analogous `lib/queimas/textos.ts`.

| Element | Copy |
|---------|------|
| Primary CTA (cartão do forno) | **"Queimar"** — opens the dois-toques tipo picker, no form. Full-width on mobile. |
| Primary CTA (índice, sem fornos) | **"Novo forno"** |
| Primary CTA (página do forno) | **"Registrar manutenção"** |
| Empty state heading (`/queimas`, no forno cadastrado) | "Nenhum forno cadastrado ainda." *(already live in the Phase 2b placeholder — reuse verbatim, wire `hrefBotao`/action this phase)* |
| Empty state body (`/queimas`, no forno cadastrado) | "Cadastre o primeiro forno para começar a contar as queimas em dois toques." |
| Empty state heading (`/queimas/relatorios`, D-08, no queima registrada) | "Nenhuma queima registrada ainda." |
| Empty state body (`/queimas/relatorios`, D-08) | "Registre a primeira queima para ver os relatórios aqui." + button "Ver fornos" → `hrefBotao="/queimas"` |
| Empty state (índice filtrado, D-05, filtro "Desativados"/"Todos" sem resultado) | Title "Nada por aqui com esse filtro." Body "Troque para 'Ativos' ou cadastre um forno novo." — same shape as Encomendas' `FRASE_FILTRO_VAZIO_*` |
| Error state (load failure, `/queimas`) | Title "Algo não funcionou." Body "Não deu para carregar os fornos. Verifique a internet e tente de novo." — mirrors `FRASE_ERRO_TITULO`/`FRASE_ERRO_CORPO` pattern from Encomendas |
| Error state (save/action failure, generic) | "Não deu para salvar. Verifique a internet e tente de novo." — reused verbatim, project-wide convention |
| Toast — queima registrada (D-04) | "Queima registrada." with action button **"Desfazer"**, duration **7 seconds** (the one exception to the 5s toast default, per `04-DESIGN-SYSTEM.md` §7) |
| Toast — desfeita | "Queima desfeita." (brief confirmation after Desfazer is pressed, ≤5s default) |
| Maintenance dialog copy | "O contador vai de **{N}** para **0**." — literal, per `04-DESIGN-SYSTEM.md` §8 and FOR-07. Fields: Responsável (optional, free text), Observações (optional) |
| Maintenance confirm button | "Registrar manutenção" |
| Destructive confirmation — excluir queima (FOR-10) | Title: "Excluir esta queima?" Body: "Ela some do histórico do Forno «{nome}» e o contador é recalculado." Confirm button: "Excluir" (destructive variant) — same `AlertDialog` shape as `ConfirmarExcluir` in Encomendas, naming what is lost |
| Desativar forno (reversible — not a deletion, no destructive styling/confirmation required per D-06) | Button: "Desativar forno". Optional light confirm copy if the planner chooses one: "O Forno «{nome}» some da lista principal, mas o histórico continua intacto. Reative quando quiser." |
| Reativar forno | Button: "Reativar forno" |
| Banner agregado (top of `/queimas`, D-nn) | "**{N} fornos precisam de atenção:** Forno 01 (95/100) · Forno 02 (103/100)" — literal template from `04-DESIGN-SYSTEM.md` §8; singular form "**1 forno precisa de atenção:** Forno 01 (95/100)" when N=1; does not render when N=0 (Claude's Discretion, confirmed sensible default in `04-CONTEXT.md`) |
| Cartão rodapé | "Última manutenção em {data} · {responsável}" or "Sem manutenção registrada" (when no manutenção exists), followed by "· {total} no total" — literal, `04-DESIGN-SYSTEM.md` §8 |
| Selo textual | "Manutenção próxima" (atenção) / "Manutenção vencida" (crítico) / nothing (ok) |
| Medidor labels | "0" / "atenção N" / "limite N" under the bar |
| Seletor de topo (D-01) | Tab labels: "Fornos" · "Relatórios" — literal route-backed tabs, not the third "Ajustes" tab from the prototype (removed per scope) |
| Relatórios — granularidade alternator | "Semana" / "Mês" (8 semanas / 6 meses recortes, FOR-12) |
| Ajuste de forno (rename/edit) | Standalone fields on forno page: Nome, Descrição, Limite — no new CTA copy needed beyond standard "Salvar" |
