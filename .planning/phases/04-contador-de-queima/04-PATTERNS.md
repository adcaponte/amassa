### `db/schema.ts` — add `tipoQueima` enum + `fornos`/`queimas`/`manutencoes` tables

**Analog:** `db/schema.ts`, the Encomendas block (lines 89-193)

**Enum + comment pattern** (lines 93-106):
```typescript
export const statusEncomenda = pgEnum("status_encomenda", [
  "rascunho", "em_producao", "concluida", "cancelada",
]);
export const etapaEncomenda = pgEnum("etapa_encomenda", [
  "producao", "secagem", "queima1", "esmaltacao", "queima2", "entrega",
]);
```
Apply the same shape for `tipoQueima = pgEnum("tipo_queima", ["biscoito", "esmalte", "ouro"])`.

**Table with `check`, index, FK `onDelete` pattern** (lines 112-136, and encomendaEtapas 169-193):
```typescript
export const encomendas = pgTable(
  "encomendas",
  {
    id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
    nome: text("nome").notNull(),
    dataInicio: date("data_inicio", { mode: "string" }).notNull(),
    status: statusEncomenda("status").notNull().default("em_producao"),
    criadoPor: uuid("criado_por").references(() => usuarios.id, { onDelete: "set null" }),
    criadoEm: timestamp("criado_em", { withTimezone: true }).notNull().defaultNow(),
    atualizadoEm: timestamp("atualizado_em", { withTimezone: true }).notNull().defaultNow(),
  },
  (tabela) => [
    check("encomendas_nome_comprimento", sql`length(trim(${tabela.nome})) between 1 and 120`),
    index("encomendas_data_inicio_idx").on(tabela.dataInicio),
  ],
);
```
For `fornos`: `nome` (check 1-80 per UI-SPEC), `limite integer default 100` with `check (limite >= 10)`, `ativo boolean default true` (no delete path — D-02/deferred). For `queimas`: `fornoId` FK `onDelete: "cascade"` (per CONTEXT deferred note — cascade stays as a manual-deletion safety net, never exposed in the app), `tipo` = `tipoQueima`, `ocorridaEm timestamptz`, `registradoPor uuid` FK to `usuarios` (`set null`, same reasoning as `criadoPor`). For `manutencoes`: `fornoId` FK cascade, `responsavel text` (optional, no check), `observacoes text` (optional), `realizadaEm timestamptz`.

**Note the fuso trap:** `queimas.ocorridaEm` and `manutencoes.realizadaEm` must be `timestamp(..., { withTimezone: true })` (an instant), NOT `date` — unlike `encomendas.dataInicio`, which is a civil date. This is the FOR-module's own §0 rule (see CONTEXT.md Specifics).

### `db/migrations/0007_*.sql` (drizzle-kit generate output) and `0008_gatilhos-queimas.sql` (hand-written triggers)

**Analog:** `db/migrations/0005_encomendas.sql` (generated) + `db/migrations/0006_gatilhos-encomendas.sql` (hand-written)

**Trigger migration pattern, verbatim structure to copy** (`0006_gatilhos-encomendas.sql`, full file):
```sql
drop trigger if exists tocar_atualizado_em_encomendas on encomendas;
--> statement-breakpoint
create trigger tocar_atualizado_em_encomendas
  before update on encomendas
  for each row execute function tocar_atualizado_em();
--> statement-breakpoint
```
Repeat once per new table that HAS `atualizado_em` (`fornos`). Decide per-table: `queimas` and `manutencoes` are append-mostly rows (a "Desfazer"/exclusão deletes rather than updates) — if the planner keeps `atualizadoEm` on them, they need the trigger too; if not, follow the `execucoes_backup` precedent (`db/schema.ts` lines 59-87) documenting the deliberate exception. This decision must be made explicitly and recorded, per the same discipline `02-MODELO-DE-DADOS.md` §0 requires.

**Reminder:** the Drizzle-generated file (`0007_*`) covers `CREATE TABLE`/`CREATE TYPE`/`FOREIGN KEY`/`CREATE INDEX` only — it does **not** emit triggers (comment at top of `0006_gatilhos-encomendas.sql`, line 1). The hand-written trigger migration is a **second, separate migration file**, applied after.

**Analog:** `lib/encomendas/cronograma.ts`

**Error discipline** (lines 176-191): one `if` per invalid case, explicit `RangeError` with a Portuguese message naming the field — never a silent default. ### `lib/queimas/relatorios.ts` (pure aggregation module)

**Analog:** `lib/encomendas/filtros.ts` (pure module, zero imports, header comment style)

**Header discipline** (lines 1-13) — zero imports, explicit documentation of what's duplicated rather than imported and why.

**Week-start-Monday / civil-day bucket arithmetic is NOT in `filtros.ts`** — `filtros.ts`'s `calcularJanelaDoHistorico` (lines 208-230) is the closest available civil-date-arithmetic pure function (12-months-back cutoff, leap-year-aware `diasNoMes` helper at lines 226-230) — reuse the **shape** of this function (string-only YYYY-MM-DD arithmetic, no `Date`) for the 8-week/6-month bucket boundaries, but the actual "semana começa na segunda, `(getDay() + 6) % 7`" rule has no existing pure-string equivalent in the codebase — `lib/encomendas/cronograma.ts`'s `diasDesdeAEpoca`/`civilDesdeDias` (lines 105-136) is the correct base to compute day-of-week from an epoch-day count without ever touching `Date`/`getDay()` directly (which is timezone-sensitive at the OS/runtime level per the CONTEXT.md fuso trap warning).
