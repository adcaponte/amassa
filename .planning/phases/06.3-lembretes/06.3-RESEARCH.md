## Summary

O bloco "Anotações" do Início é um Server Component `async` (`components/amassa/inicio/bloco-anotacoes.tsx`) com `try/catch` próprio, dentro de um `Suspense` próprio em `app/gestao/(app)/page.tsx`, e entrega a folha a um Client Component (`editor-de-anotacoes.tsx`) que semeia o estado **uma vez** e nunca é substituído por revalidação. A fase cresce esse bloco para duas colunas e acrescenta um módulo `lib/lembretes/` + `components/amassa/lembretes/` + a rota `/gestao/lembretes`, sem pacote novo: `sonner` 2.0.8 já é o sistema de toast (montado uma vez no layout de `/gestao`), e o padrão de caixinha otimista (`components/amassa/abertura/caixa-marcacao.tsx`, botão `aria-pressed` de 44 px, estado desejado) e de linha com estado local (`linha-tarefa.tsx`) já existem — com o aviso documentado de que **a re-renderização do servidor depois de uma Server Action às vezes não chega à tela** (≈54% medido em `.planning/debug/abertura-navegacao-trava.md`), então o estado da lista tem de ser local e deduzido, nunca dependente do redesenho.

**D-04 está resolvido sem mudança de código:** `textoDaAutoria` (`lib/anotacoes/folha.ts:65-78`) formata com `timeZone: "America/Sao_Paulo"` explícito, e o teste `tests/unit/anotacoes-folha.test.ts:43-47` (`17:20Z → "14h20"`) roda no CI (`npm test` em `.github/workflows/entrega.yml:44`, runner em UTC) — se a função usasse o fuso do processo, o CI daria "17h20". Recomenda-se só **um caso a mais** no teste (instante que vira o dia em UTC) como prova explícita do D-04. A formatação é "14h20" (não "14:20" do protótipo); como "a folha não muda", **mantenha "14h20"**.

A exclusão adiada (D-03) casa exatamente com o `sonner` instalado: `onAutoClose` dispara **só** quando o timer expira; o clique em "Desfazer" (action) fecha o toast **sem** chamar `onAutoClose` nem `onDismiss`; deslizar o toast chama `onDismiss`. O timer **pausa** com o mouse sobre o toaster, com o toaster expandido e com a aba escondida — o e2e precisa tirar o mouse de cima e usar `expect.poll` com folga. Não existe hoje nenhuma checagem global "nenhuma tabela permite DELETE": cada módulo prova o próprio `revoke` em `scripts/testar-migracoes.mjs`, e `fornecedor_anexos`, `documento_linhas`, `ficha_tecnica`, `abertura_*`, `eventos`, `inscricoes` etc. **já mantêm** o delete. Logo, nenhuma checagem existente precisa de exceção; o que falta é a prova **positiva** do delete em `lembretes` (molde: `conferirFornecedores`, que já afirma que `fornecedor_anexos` MANTÉM o delete).

**Primary recommendation:** 0029 gerada por `npm run db:generate -- --name lembretes` + trigger à mão e **sem** revoke (com comentário); regras em `lib/lembretes/regras.ts` (puro, reusa `lib/producao/calendario.ts`); o Início carrega todos os abertos (com teto) e o cliente deduz ordem/6/"e mais N"/contagens pelo módulo puro; exclusão adiada num armazém de "exclusões pendentes" de nível de módulo + `toast(..., { duration: 6000, onAutoClose, onDismiss })`; "ver todos" por URL (`?ver`, `?quem`, `?quantos`); `/api/health/lembretes` no molde de `/api/health/fornecedores`.

### Pattern 1: O bloco duplo, com falha isolada por coluna
**What:** `BlocoAnotacoes` mantém `data-testid="inicio-bloco-anotacoes"` (o `inicio.spec.ts:75-81` afirma a ordem dos 5 blocos por esse testid), troca o título para "Anotações e lembretes", ganha o link "ver todos os lembretes" pelas props já existentes `acaoRotulo`/`acaoHref` de `BlocoDoInicio`, e ocupa as duas colunas da grade (`md:col-span-2`). Dentro, duas colunas a partir de ~820 px (protótipo: `@media(min-width:820px){.bloco{grid-template-columns:1fr 1.1fr}}`), empilhadas abaixo.
**Por que `try/catch` por coluna:** entre o `implantar` e o `db:migrate` da 0029, `select … from lembretes` falha; a folha (`anotacoes_da_casa`, 0022) continua funcionando. Um `try` único derrubaria a folha junto. Ler as duas com `Promise.allSettled`.
**Fallback do Suspense:** `app/gestao/(app)/page.tsx:79` usa `<BlocoEsqueleto titulo="Anotações" linhas={4} />` — atualizar título e o esqueleto para `md:col-span-2` também (senão o layout pula quando o conteúdo chega).

### Pattern 3: Regras puras e testadas (`lib/lembretes/regras.ts`)
Importa só `@/lib/producao/calendario` (`diasEntre`, `formatarDiaMes`, `ehDataCivil` — puros, já reusados por `lib/fornecedores/esquemas.ts`) — e um teste de pureza no molde de `tests/unit/agenda-semana.test.ts:266-275`.
```ts
// Ordem dos abertos (BRIEFING §3; protótipo `ordem()`): para_quando asc, sem data por último, empate criado_em.
export function compararAbertos(a: Aberto, b: Aberto): number {
  const ka = a.paraQuando ?? "9999-12-31", kb = b.paraQuando ?? "9999-12-31";
  if (ka !== kb) return ka < kb ? -1 : 1;
  if (a.criadoEm !== b.criadoEm) return Date.parse(a.criadoEm) - Date.parse(b.criadoEm);
  return a.id < b.id ? -1 : a.id > b.id ? 1 : 0; // desempate estável, igual ao SQL
}
// Rótulo (protótipo `quandoTxt()`): hoje → "hoje"; −1 → "venceu dd/mm · ontem"; −N → "venceu dd/mm · N dias";
// +1 → "amanhã"; demais → "dd/mm"; sem data → null. Tom: "vencido" | "hoje" | "normal".
export function rotuloDoPrazo(paraQuando: string | null, hoje: string): RotuloDoPrazo | null
// Cabeçalho + 6 + "e mais N" (protótipo `desenhar()`): LIMITE_NO_INICIO = 6.
export function resumoDoBloco(abertos: readonly Aberto[], hoje: string): {
  visiveis: Aberto[]; restantes: number; abertos: number; vencidos: number }
// "por X · dd/mm hh:mm" / "feito por Y · dd/mm hh:mm" — Intl com timeZone "America/Sao_Paulo", hourCycle h23.
```
SQL da página "ver todos" usa **a mesma** ordem: `order by para_quando asc nulls last, criado_em asc, id asc` (Postgres põe `NULL` por último em `asc` por padrão, mas escreva `nulls last` explícito). Feitos: `order by feito_em desc, id desc`.
⚠ Briefing diz "venceu dd/mm · N dias"; o protótipo (que vence na interface) escreve **"ontem"** para 1 dia. Use o protótipo e registre no plano.

### Pattern 6: Exclusão adiada (D-03) com o `sonner` instalado
Comportamento lido em `node_modules/sonner/dist/index.mjs` [VERIFIED nesta sessão]:
- linhas 655-665: o timer chama `toast.onAutoClose(toast)` e depois `deleteToast()` — **só** na expiração;
- linhas 667-671: o timer **pausa** se `expanded || interacting || isDocumentHidden` (mouse sobre o toaster, toque, aba escondida);
- linhas 876-885: clicar na `action` chama `action.onClick` e `deleteToast()` — **não** chama `onDismiss` nem `onAutoClose`;
- linhas 680-686, 772, 848: `toast.dismiss(id)`, deslizar e o botão de fechar chamam `onDismiss`.
```ts
// components/amassa/lembretes/avisos.ts (client)
export function avisarExcluido(l: { id: string; texto: string }) {
  esconder(l.id);                                   // armazém de exclusões pendentes (nível de módulo)
  let resolvido = false;
  const efetivar = () => { if (resolvido) return; resolvido = true;
    void excluirLembrete({ id: l.id }).then((r) => { if (!r.ok) { mostrar(l.id); toast.error(r.erro); } else confirmar(l.id); })
      .catch(() => { mostrar(l.id); toast.error(FRASE_FALHA_AO_EXCLUIR); }); };
  toast(textoExcluido(l.texto), {
    duration: 6000,
    action: { label: ROTULO_DESFAZER, onClick: () => { if (resolvido) return; resolvido = true; mostrar(l.id); } },
    onAutoClose: efetivar,
    onDismiss: efetivar,        // deslizar o toast = aceitar a exclusão
  });
}
```
- **Armazém de nível de módulo** (`useSyncExternalStore`), não `useState` do componente: o `<Toaster>` vive em `app/gestao/(app)/layout.tsx` e sobrevive à navegação interna; se a pessoa for do Início a `/gestao/lembretes` dentro dos 6 s, a nova tela também precisa esconder o id (o servidor ainda o devolve), e o `onAutoClose` ainda efetiva.
- A lista local filtra `exclusoesPendentes` **sobre** as props do servidor — senão uma revalidação vinda de outra ação (criar, marcar) devolve a linha à tela no meio dos 6 s.
- `excluirLembrete`: `delete from lembretes where id=$1 returning id`; 0 linhas → `{ ok: true, jaExcluido: true }` (dois toques/duas abas). Nunca 500.
- Feito com Desfazer: **não** adia — `marcarFeito({feito:true})` na hora (o feito não apaga nada), e o Desfazer manda `feito:false` (molde `avisarDispensada`, `components/amassa/agenda/confirmar-dispensar.tsx:50-78`: flag `desfeito` contra toque duplo).
- Duração explícita (`duration: 6000`) — o padrão do Toaster é 5000 (`layout.tsx`).

### Anti-Patterns to Avoid
- **Depender do redesenho do servidor para mostrar o resultado de um toque** — falha em silêncio (debug doc da Abertura). Estado local deduzido; o servidor confirma.
- **`router.refresh()` depois da ação** — a ação já revalida; o refresh extra piorou a taxa de falha medida (`caixa-marcacao.tsx`, comentário de `alternar()`).
- **Calcular "hoje" no cliente** (`new Date().toISOString().slice(0,10)` como no protótipo) — UTC à noite. `hoje` vem da página por prop.
- **`current_date` no SQL para "vencido"** — o Postgres roda em UTC; passe `hoje` como parâmetro.
- **Contar abertos só da fatia visível** — o Início precisa de TODOS os abertos (teto, ex. 500) para "N abertos · M vencidos" e "e mais N" corretos depois de toques otimistas.
- **Tamanhos do protótipo abaixo do mínimo** — pílulas 36 px, botões "editar/excluir" 34 px, `input type=date` 13 px, campo 15 px: tudo sobe para 44 px / 16 px (`text-corpo`).

## Common Pitfalls

### Pitfall 1: O timer do toast pausa e o e2e da exclusão fica esperando para sempre
**What goes wrong:** o teste clica "excluir", espera 6 s e a linha ainda está no banco.
**Why:** `sonner` pausa o timer com o mouse sobre o toaster (`expanded`) ou tocando nele (`interacting`) — `index.mjs:667-671`.
**How to avoid:** depois do clique, `await page.mouse.move(0, 0)`; provar com `await expect.poll(() => lerLembrete(id), { timeout: 15_000 }).toBeNull()` (nunca `waitForTimeout`). Provar também o lado inverso: "excluir" + "Desfazer" → a linha **continua** no banco depois de >6 s.
**Warning signs:** o teste passa no desktop e falha no celular (toast em largura cheia embaixo, onde o dedo estava).

### Pitfall 2: A linha excluída volta à tela no meio dos 6 s
**Why:** qualquer outra ação revalida `/gestao` e o servidor ainda tem a linha.
**How to avoid:** a lista renderiza `props − exclusõesPendentes`; o armazém é de módulo.

### Pitfall 3: Página fechada = lembrete não apagado
**Aceito pelo dono (D-03).** Não "consertar" com `beforeunload`/`sendBeacon` — não é pedido, e uma ação disparada no `pagehide` pode ou não chegar. Registrar no SUMMARY e na verificação humana como comportamento esperado.

### Pitfall 4: CLAUDE.md §Exclusão × toast com Desfazer
"Toda remoção pede confirmação e diz o que será perdido." O protótipo aprovado (vence na interface) exclui com um toque + Desfazer. Para não ser "silenciosa": o toast diz **o quê** ("Lembrete excluído: pedir argila…" — o protótipo diz só "Lembrete excluído."; acrescentar o texto truncado como o "Feito: …" faz). Registrar no plano como exceção consciente, decidida pelo dono no briefing (§3) — o planner não deve inventar um diálogo de confirmação. [ASSUMED: redação exata do toast — discrição de Claude pela CONTEXT]

### Pitfall 5: Contagens globais disputadas por desktop e celular no e2e
**Why:** os dois projetos rodam em paralelo contra o mesmo banco; "6 + e mais N", "N abertos · M vencidos", "Feitos (N)" são globais.
**How to avoid:** trava consultiva por arquivo (molde `tests/e2e/apoio/travar-anotacoes.ts`, chave nova — as em uso são `819_224`, `726623`, `TRAVA_DO_PRECO_DA_HORA`, `TRAVA_DO_DIA_DA_AGENDA`), `test.describe.configure({ mode: "serial" })` e, dentro da trava, `delete from lembretes` no início de cada caso que afirma contagem (a tabela só existe para esta fase; o e2e é efêmero). O estado vazio da semente vai para `@vazio-global` (cadeia `vazio-*`), nunca `--grep`.

### Pitfall 6: Fuso
- "Hoje" do e2e: `hojeNoAtelie()` / `somarDiasAoHoje(n)` de `tests/e2e/apoio/semear-financeiro.ts:163-178` — nunca `toISOString()` (quebra das 21h às 24h de Brasília).
- Teste unitário da virada: `hojeEmBrasilia(new Date("2026-10-03T02:30:00Z"))` = `"2026-10-02"` → um lembrete para `2026-10-02` é "hoje", não "venceu".

### Pitfall 7: `tsc` acusa `.next/types` velhos depois de trocar de branch
Apagar `.next/types` e rodar de novo (memória do projeto). Aparece como TS2307 em rota que não existe mais.

### Pitfall 8: `"use server"` exporta só funções async
Constantes, tipos-valor e funções síncronas não podem sair de `acoes.ts` (viram erro de build/endpoint). Frases em `textos.ts`, esquemas em `esquemas.ts`.

### Pitfall 9: Esqueleto e grade
O 5º bloco hoje ocupa uma coluna de `md:grid-cols-2`. Ao virar `md:col-span-2`, o `BlocoEsqueleto` correspondente precisa do mesmo `col-span` e de linhas suficientes (D-09: a página não pode pular).

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Ação chamada sem sessão (endpoint de Server Action) | Spoofing/EoP | `exigirUsuario()` primeira linha; `verificar-acoes` |
| Texto do lembrete com HTML/script | Tampering (XSS) | React escapa; `toast()` recebe **string** (nunca `jsx`/`dangerouslySetInnerHTML`) |
| `quem` apontando para usuário desativado/inexistente | Tampering | checagem de gestor ativo + FK (23503 → frase humana) |
| Exclusão em massa por chamada direta da ação | Tampering/Repudiation | aceito pelo desenho (casa pequena, todos autenticados); ação apaga **um** id validado por Zod; sem histórico (fora do escopo §5) |
| Rota de saúde pública vazando dado | Information disclosure | corpo só `{ status }`, `limit(1)` descartado (molde T-06.2-45); e2e com `toEqual({status:"ok"})` |
| Dado real em teste (repo público) | Information disclosure | prefixo `[e2e]`/`[mig]`, nomes inventados |
