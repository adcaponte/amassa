**5. `lib/encomendas/cronograma.ts` — o núcleo, sem nenhum import.** Exporte:
`type Etapa` (a união dos seis literais), `ORDEM_DAS_ETAPAS` (readonly, na ordem fixa),
`ETAPAS_MARCO` (`queima1`, `queima2`, `entrega`), `DIAS_PADRAO` (`producao: 3`, `secagem: 6`,
`queima1: 1`, `esmaltacao: 1`, `queima2: 1`, `entrega: 1`),
`type DuracaoDeEtapa = { etapa: Etapa; dias: number }`,
`type FaixaDeEtapa = { etapa: Etapa; dias: number; marco: boolean; inicio: string; fimExclusivo: string; ultimoDia: string | null; desenhada: boolean }`,
`type Cronograma = { inicio: string; fimExclusivo: string; duracaoTotalEmDias: number; dataDeConclusao: string | null; faixas: FaixaDeEtapa[] }`
e `function calcularCronograma(dataInicio: string, duracoes: readonly DuracaoDeEtapa[]): Cronograma`.

Regras que o código precisa carregar, cada uma como um ramo próprio com retorno/tratamento
explícito (a forma de `frescor.ts`: um `if` por caso, nunca um `default` que engole):
`fim exclusivo` — `fimExclusivo` de uma etapa é o `inicio` da seguinte, e `ultimoDia` (o que a
interface mostra como "fim") é o dia anterior a `fimExclusivo`, `null` quando `dias === 0`;
etapa de `dias === 0` tem `desenhada: false`, `inicio === fimExclusivo` e não avança o cursor;
`duracaoTotalEmDias` é a soma dos `dias`; `dataDeConclusao` é o `ultimoDia` da última etapa com
`dias > 0`, e `null` quando todas as seis estão em 0.
Datas trafegam como string `YYYY-MM-DD` do começo ao fim. A aritmética interna usa `Date.UTC(ano,
mes-1, dia)` e volta para string — nunca `new Date("...")` sobre a string crua nem `getDate()` de
um `Date` local, que é onde o fuso do runtime desloca o dia.

## Decisões do planejador (o que a fonte deixou aberto e este plano fecha)

Estas não estavam em `03-CONTEXT.md` nem no `03-UI-SPEC.md` — foram decididas aqui em vez de
deixadas para o executor improvisar.

- **PD-01 — Nome longo no título dos dois `alert-dialog` (E8/E9 `long-text`, marcado
  `unresolved` no UI-SPEC).** O nome **quebra em linha, nunca trunca**: `AlertDialogTitle` recebe
  `[overflow-wrap:anywhere]` e o conteúdo do diálogo `max-h-[85svh] overflow-y-auto`. Truncar um
  nome dentro de uma pergunta de confirmação destrutiva é exatamente onde truncar custa caro — a
  pessoa precisa reconhecer o que vai apagar. Implementado no plano 05.
- **PD-02 — Corrida entre duas gravações rápidas na mesma etapa ou no mesmo item (item transversal
  do UI-SPEC, marcado `unresolved`).** Nem *debounce* nem fila: (a) o controle fica `disabled`
  enquanto a gravação está em voo — o spinner já ocupa o lugar do número, então um segundo toque
  não chega a ser emitido; (b) **a Server Action nunca recebe valor absoluto vindo do cliente**.
  `ajustarEtapaEncomenda` recebe `{ encomendaId, etapa, delta }` (ou `{ ligado }` no marco) e
  calcula o novo valor a partir da linha lida DENTRO da transação, com `select ... for update`.
  Se duas gravações chegarem mesmo assim, o resultado é a soma dos dois incrementos, nunca uma
  atualização perdida. `reordenarItemEncomenda` recebe `{ itemId, direcao }` e troca `ordem` com o
  vizinho na mesma transação, também com `for update`. Implementado no plano 03.
- **PD-03 — A geometria do Gantt mora em `lib/encomendas/gantt.ts`, um segundo módulo puro.**
  `cronograma.ts` é sobre datas e não pode crescer nem importar; a geometria (18px/dia, intervalo
  desenhado com quinzena de folga, células de quinzena, posição de "Hoje", rolagem de abertura)
  precisa de teste de unidade que meça píxel — um e2e sozinho diz que quebrou, não onde.
  Implementado no plano 02.
- **PD-04 — Sem `date-fns`.** A formatação de data usa `Intl.DateTimeFormat("pt-BR", { timeZone:
  "America/Sao_Paulo" })` num módulo puro `lib/encomendas/formato.ts`. Precedente do próprio
  projeto: a 02a-02 calculou a data de Brasília com `Intl` nativo em vez de instalar `date-fns-tz`.
  Um pacote a menos num repositório público, e a aritmética de dia civil já vive em `cronograma.ts`
  sobre strings `YYYY-MM-DD`, que é onde ela precisa estar. `CLAUDE.md` lista `date-fns` como stack
  previsto — esta é uma divergência consciente do planejador, registrada para ser revista se a
  formatação crescer.
- **PD-05 — Datas trafegam como string `YYYY-MM-DD` em todas as camadas**, nunca como `Date`.
  `data_inicio` é `date(..., { mode: "string" })` no Drizzle. É a resposta estrutural à categoria
  `precision` de quase todos os requisitos: um `Date` atravessando a fronteira servidor/cliente
  desloca o dia sem avisar.
