## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4.1.10 (unit) · Playwright ^1.62.1 (e2e, projects `desktop`/`celular` + the `vazio-*` chain) · `scripts/testar-migracoes.mjs` (ephemeral Postgres 17) · `scripts/testar-backup.mjs` (Docker) |
| **Config file** | `vitest.config.ts` (`include: ["tests/unit/**/*.test.ts"]`), `playwright.config.ts` |
| **Quick run command** | `npx vitest run tests/unit/fornecedores-*.test.ts tests/unit/middleware-matcher.test.ts` + `npx tsc --noEmit` |
| **Full suite command** | `npm run verificar` (lint, `tsc --noEmit`, `verificar-acoes`, `npm test`, `test:migracoes`) |
| **Estimated runtime** | ~5 s quick · ~3–4 min `verificar` (includes the ephemeral Postgres of `test:migracoes`) |

`npm run test:e2e` costs ~53 s of fixed tax before the first test (15 s Postgres + 38 s `next build`).
Per `.claude/CLAUDE.md`: at most ONE invocation per plan, always with `--grep` on what the plan
touched; never `npm run build` as a separate step; the un-grepped full sweep runs ONCE per phase, in
the last plan (the gate). If a `--grep` fails and the full suite is needed to diagnose, run it and
record it in the SUMMARY. `npm run test:backup` runs once in the file-infrastructure plan and once in
the gate. Windows Defender scans may slow builds: re-run a timed-out test once before calling it a
defect.

## Sampling Rate

- **After every task commit:** the quick run above; `npm run test:migracoes` in every task that touches `db/schema.ts` or the 0028 migration
- **After every plan:** `npm run verificar` + one `npm run test:e2e -- --grep "fornecedores <slice>"`
- **Before `/gsd-verify-work`:** `npm run verificar` green + one full `npm run test:e2e` sweep + `npm run test:backup` (gate plan)
- **Max feedback latency:** ~10 s for the quick run
