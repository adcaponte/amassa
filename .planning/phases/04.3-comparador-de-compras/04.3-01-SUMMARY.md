- **Preço em duas etapas deliberadas:** a Tarefa 1 implementou só o suficiente de `converterPrecoParaCentavos` para o traçado real (as quatro formas + campo vazio); a Tarefa 2 completou TDD-primeiro as recusas (grupo de milhar mal formado, teto de dez milhões) — RED confirmado (3 testes falhando pelo motivo certo) antes do GREEN.

- **Dois "+ Nova cotação" visíveis ao mesmo tempo quando a categoria está vazia** (barra do painel + estado vazio da lista) — replica deliberadamente o padrão já em produção de `botao-adicionar-abertura.tsx` + `EstadoVazio`, não uma duplicação acidental.
- **Sem toast de sucesso ao salvar cotação** — divergência deliberada do §Copywriting Contract do UI-SPEC, documentada no próprio código: a navegação completa (D-23) não deixaria o toast sobreviver, e a lista já atualizada é a confirmação (mesmo precedente de `formulario-item.tsx`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] shadcn CLI importou `cn` de pacote npm de terceiro em vez de `@/lib/utils`**
- **Found during:** Tarefa 1, instalação de `textarea`/`checkbox`
- **Issue:** `npx shadcn@3.8.5 add textarea checkbox` gerou `import { cn } from "cn"` e adicionou a dependência `cn@0.3.0` ao `package.json`/`package-lock.json` — inconsistente com o resto do projeto, que sempre usa o `cn` local de `@/lib/utils`.
- **Fix:** Editados os dois arquivos para importar de `@/lib/utils`; revertida a entrada `cn` de `package.json` e `package-lock.json` (via `git checkout`, sem rodar `npm install` de novo para não introduzir ruído de lockfile de plataformas opcionais).
- **Files modified:** `components/ui/textarea.tsx`, `components/ui/checkbox.tsx`, `package.json`
- **Verification:** `npx tsc --noEmit` e `npm run lint` limpos; `git diff -- package.json package-lock.json` vazio antes do commit.
- **Committed in:** `ce38933` (Tarefa 1)

**2. [Rule 1 - Bug] Nome acessível inconsistente e locators ambíguos, achados pelo próprio e2e**
- **Found during:** Tarefa 1, execução de `npm run test:e2e -- --grep "cotacoes tracador"` (invocado 4 vezes — ver nota de orçamento abaixo)
- **Issue:** (a) `PilulaNovaCategoria` tinha `aria-label="Criar nova categoria"` enquanto `BotaoVazioCotacoes` (o mesmo botão, no estado vazio) usava só o texto "+ Nova categoria" — dois nomes acessíveis para a mesma ação; (b) o locator do e2e usava `.or()` sem filtrar por visibilidade, e cartão/linha da mesma cotação convivem no DOM (alternados só por CSS) — modo estrito do Playwright reprovava por ambiguidade; (c) "+ Nova cotação" aparece em dois lugares ao mesmo tempo (barra do painel + estado vazio da lista) quando a categoria está vazia.
- **Fix:** Removido o `aria-label` de `PilulaNovaCategoria` (o texto visível já é suficiente); locators do teste passaram a usar `.filter({ visible: true })` e `.first()` onde dois elementos legítimos coexistem.
- **Files modified:** `components/amassa/cotacoes/pilula-nova-categoria.tsx`, `tests/e2e/cotacoes-tracador.spec.ts`
- **Verification:** `npm run test:e2e -- --grep "cotacoes tracador"` — 24/24 passando (dois projetos: desktop e celular).
- **Committed in:** `54db0b4`
