## Decisions Made

- **Canal local no abridor para categoria (`abrirCategoriaParaEditar`):** abrir o diálogo de renomear é `history.pushState`, que nunca busca dado novo do servidor — a prop `categoriaParaEditar` só reflete a navegação anterior. Sem um canal local (mesmo padrão já usado para cotação), o campo de nome abria vazio no primeiro toque. Achado real pelo próprio e2e (não suposição), corrigido antes do commit.
- **Dois modais nunca simultâneos:** o botão "Excluir categoria" troca `categoriaDialogo` por `categoriaRemover` na URL (fecha o `Dialog`, abre o `AlertDialog`) em vez de deixar os dois Radix `Root` abertos ao mesmo tempo — mesma cautela que o UI-SPEC já registra para `Dialog`+`Sheet`, aplicada aqui a `Dialog`+`AlertDialog`.
- **Fronteira de erro provada por URL malformada, não por quebra de código temporária:** `?categoriaDialogo=nao-e-um-uuid` aciona a consulta real `obterCategoriaDeCotacao` com um identificador inválido, que o Postgres recusa (`invalid input syntax for type uuid`) — a exceção não é capturada na página de propósito, então cai na fronteira de erro da rota. Confirmado no log do servidor durante o e2e (a mensagem crua do Postgres aparece SÓ no console, nunca na tela).
