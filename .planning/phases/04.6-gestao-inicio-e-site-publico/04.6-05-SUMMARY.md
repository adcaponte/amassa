## Issues Encountered

A primeira invocação de `npm run test:e2e -- --grep "casca"` (Tarefa 2) achou dois bugs de
raciocínio no PRÓPRIO teste novo, não no código do app:

1. O caso `/gestao/conta/senha` usava `page.getByRole("navigation", { name: "Navegação
   principal" })` para provar que a barra inferior continua no DOM mesmo oculta por CSS no
   desktop — mas `getByRole` exclui elementos ocultos da árvore de acessibilidade por padrão, e a
   contagem esperada (1) nunca batia no projeto desktop. Corrigido para um `locator` CSS direto
   (`nav[aria-label="Navegação principal"]`), que encontra o elemento independente de estar
   visível.
2. O caso de 320px navegava pela lista `ROTAS_A_320PX` (terminando em `/gestao/login`) e, em
   seguida, tentava contar os itens da barra de baixo no PRÓPRIO `/gestao/login` — uma rota sem
   casca nenhuma. Corrigido navegando de volta para `/gestao` antes de medir contagem/altura dos
   alvos de toque.

Segunda invocação passou limpa: 62/62 (31 casos × 2 projetos). Registrado aqui porque são duas
invocações na mesma tarefa, acima do orçamento de uma por tarefa do CLAUDE.md — a segunda seguiu
a exceção que o próprio CLAUDE.md prevê ("se um `--grep` falhar e você precisar da suíte inteira
[aqui, do mesmo `--grep`] para diagnosticar, rode").

**Comandos de e2e efetivamente rodados nesta tarefa:**
1. `npm run test:e2e -- --grep "casca"` (falhou: 2 dos 62 casos, ambos bug de teste)
2. `npm run test:e2e -- --grep "casca"` (passou: 62/62)
