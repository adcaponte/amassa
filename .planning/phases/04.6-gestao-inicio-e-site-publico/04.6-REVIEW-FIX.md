### CR-01: 65 in-app navigation sites still target the old root addresses

**Files modified:**
- 37 components/pages (the 16 part-A sites and the 49 part-B sites the review listed)
- `lib/financeiro/navegacao.ts`
- `tests/unit/financeiro-navegacao.test.ts`
- `tests/unit/sem-rota-antiga.test.ts` (new)

**Commits:** `2604b1a` (RED), `cc797be` (fix)

**Applied fix:**

1. **Guard first, seen RED.** `tests/unit/sem-rota-antiga.test.ts` walks `app/`, `components/` and
   `lib/` (`*.ts`, `*.tsx`) through the **TypeScript AST**, not a line regex.
   - It flags a string literal, no-substitution template, or template head whose value *begins*
     with an old path. An old path means: at the end of the literal, or followed by `/`, `?` or `#`.
   - The old paths are **derived from `REDIRECIONAMENTOS_ANTIGOS`**: the static prefix of each
     `source`, so `/encomendas/:id` becomes `/encomendas`. None is hardcoded.
   - Comments are not literals, so they never trip it. Site anchors (`#encomendas`) do not start
     with `/`.
   - A literal that is an argument of `rotaDeGestao(...)` is exempt. The exemption only passes
     through ternary, parentheses, `+`, template and `as`. A literal passed to any other call
     first, like `rotaDeGestao(outra("/x"))`, is still flagged. A small fixture test pins this rule.
   - `lib/rotas/redirecionamentos-antigos.ts` is excluded.
   - First run: **65 offenders**, the review's exact count.
2. **New builder `hrefDoOrcamento(orcamentoId, extras?)`**, a sibling of `hrefDoCaixa`.
   - It replaces the 25 hand-built `/financeiro?aba=orcamentos&orcamento=…` sites.
   - `extras` keep the original parameter order.
   - It has 3 unit tests.
   - `hrefDoCaixa` now uses `PREFIXO_GESTAO` instead of a literal.
3. **`hrefDaAbaPecas`** now covers the 3 Peças sites that bypassed it (`dialogo-ficha.tsx` ×2,
   `lista-pecas.tsx`).
   - One behaviour difference: hiding the exclusive pieces now leaves no `exclusivas` parameter
     instead of `exclusivas=0`.
   - The page only reads `=== "1"`, so the result is the same.
4. **Everything else goes through `rotaDeGestao(...)`**: abertura, cotações, cadastros, the caixa
   and venda/despesa notices, and the month navigation in `financeiro/page.tsx`.
5. **`formulario-forno.tsx`:** the half-fixed ternary is now
   `rotaDeGestao(cond ? \`/queimas/${id}\` : "/queimas")` in both places. There is no double
   prefix.
6. **The test went RED to GREEN.**
   - `tsc` and `lint` are clean.
   - The first pass was run through Prettier, which reformatted whole files that were never
     Prettier-clean. That was reverted with `git checkout` before committing, so the diff holds
     only the navigation changes (156+/68−).

**Deviation from the review's suggestion:** The review suggested sibling builders for abertura and
cotações too. Those sites build their query strings in many shapes: conditional `categoria`,
`query` strings assembled elsewhere, and several dialog parameters. Wrapping them in
`rotaDeGestao` preserves each URL exactly. A builder would have changed some of them, for
example dropping `categoria=null`. The structural test prevents regression either way.

### CR-02: Anotações — a pending save is cancelled on unmount while the indicator reads "salvo"

**Files modified:**
- `lib/anotacoes/agendador.ts` (new, pure)
- `components/amassa/inicio/editor-de-anotacoes.tsx`
- `lib/anotacoes/textos.ts`
- `tests/unit/anotacoes-agendador.test.ts` (new)

**Commits:** `c2f4738` (RED), `af5383e` (fix)

**Applied fix:**

- **The rule moved out of the component.** The decision logic now lives in
  `criarAgendadorDeGravacao`, which has no React, no database and no `window`, only
  `setTimeout`/`clearTimeout`. The component only wires it up.
- **Flushing replaces cancelling.** On unmount, `encerrar()` now **descarrega**: it sends the
  pending text immediately. If a save is already in flight, the pending text is sent when it
  finishes. After `encerrar()`, no further `aoMudar` calls happen, which keeps the old
  no-setState-after-unmount concern. In-flight and chained saves still run to completion.
- **Hidden page.** `visibilitychange` → hidden and `pagehide` also flush. This covers a locked
  phone and switching tabs.
- **Tab close or reload.** A `beforeunload` guard runs whenever `temAlteracaoNaoSalva()` is true,
  which includes a save in flight. It uses `FRASE_ALTERACOES_NAO_SALVAS`, in Portuguese.
- **Indicator.** A new `"pendente"` state shows **"editando…"** from the first keystroke until the
  save that covers it succeeds. The indicator never reads "salvo" while there is unsaved text.
- **Network failure.** A rejected server-action promise now shows as "erro" on screen instead of
  becoming an unhandled rejection.

### CR-03: Anotações — stale `vistoEm` closure makes a user conflict with their own save

**Files modified:** same as CR-02
**Commits:** `c2f4738` (RED), `af5383e` (fix)

**Applied fix:**

- **Latest version at send time.** The version is read when a save fires, not captured when the
  keystroke happens.
- **Single flight.** Only one save is ever in the air. Text typed during a flight waits and is
  sent afterwards, with the version that flight returned.
- **Typing during a conflict.** It no longer hides the warning and no longer autosaves over it,
  since that would only reproduce the conflict. The warning waits for "manter o meu", which sends
  the **latest** text with the server's version, or for "ver o dela". The misleading comment is
  gone.

**Tests (fake timers, 18 cases):** they cover:
- flush on dispose, including dispose during a flight
- no notifications after dispose
- latest version used after an in-flight save
- max 1 save in flight
- a simulated server applying `decidirGravacao`'s rule, where one person typing across their own
  saves gets **zero** conflicts
- the error path and the network rejection path
- conflict behaviour, "manter o meu" and "ver o dela"

**RED evidence:**
- The test file was committed while the module did not exist.
- Before committing it, a faithful port of the **old** editor behaviour was run against the tests
  (not committed): **13 of 18 failed**, including every CR-02 and CR-03 case.
- With the real module: 18/18 passing.

The server side (`lib/anotacoes/acoes.ts`) was not rewritten. WR-03 below only adds a revalidation
after the transaction.

### WR-03: Início is never revalidated after `salvarAnotacoes`

**Files modified:** `lib/anotacoes/acoes.ts`
**Commit:** `9605a8d`

**Applied fix:**
- `revalidatePath(rotaDeGestao("/"))` runs after a successful write.
- It sits **outside** the transaction and outside the `try`, so a failure there can never report
  "não deu para salvar" for text that is already stored.
- `exigirUsuario()` stays on the first line: `verificar-acoes` reports 74 actions, 0 violations.
- As the orchestrator confirmed, no parent passes a `key`, so the mounted editor keeps its text.

**Cost to know about:** every autosave now re-renders the Início's server blocks. Each is one
round of five small queries, and there are two users.
