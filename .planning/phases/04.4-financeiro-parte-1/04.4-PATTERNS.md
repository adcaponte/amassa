### `db/schema.ts` — new tables (model, CRUD)

**Analog:** `db/schema.ts` lines 300-343 (`aberturaItens`) and lines ~480-510 (`cotacoes`)

**Money-as-centavos-integer pattern** (lines 308, 322-328):
```typescript
valorCentavos: integer("valor_centavos").notNull(),
// ...
check(
  "abertura_itens_valor_nao_negativo",
  sql`${tabela.valorCentavos} >= 0 and ${tabela.valorCentavos} <= 1000000000`,

```
Apply this exact ceiling (10^9 centavos = R$10 milhões) with a table-specific check name for every money column: `documento_linhas.valor_unitario_centavos`, `parcelas.valor_centavos`, `contas_fixas.valor_esperado_centavos`, `configuracao_financeira.saldo_inicial_centavos`, etc. **Note the CONTEXT.md discretion point: the project convention (centavos integer) should be followed instead of the briefing's `numeric(12,2)` proposal** — this is confirmed by both D-Claude's-Discretion and this analog.

**Enum + table + check + index pattern** (lines 279-343): declare `pgEnum` for `grupo` (`receita|custo|geral|fora`), `area` (`cafeteria|espaco|pecas|loja|geral`), `forma` (`dinheiro|pix|cartao`), `tipoDocumento` (`venda|despesa`) the same way `categoriaItemAbertura`/`formaPagamentoAbertura` are declared just above line 280.

**String length check pattern** (line 322):
```typescript
check("abertura_itens_nome_comprimento", sql`length(trim(${tabela.nome})) between 1 and 120`),
```
Reuse verbatim shape for `categorias.nome`, `itens_catalogo.nome`, `contas_fixas.nome` (1-120 per UI-SPEC Assunções #7).

**Single-row config table pattern** (lines 377-392, `aberturaConfiguracao`):
```typescript
unique("abertura_configuracao_linha_unica_uk").on(tabela.linhaUnica),
check("abertura_configuracao_linha_unica", sql`${tabela.linhaUnica}`),
```
Copy directly for `configuracaoFinanceira` (taxa_cartao_percentual, saldo_inicial, data_saldo_inicial — a single settings row).

**Optional FK with `set null` pattern** (line 357-358): `contas_fixas.categoria_id`, `documento_linhas.item_id` should use `.references(() => ..., { onDelete: "set null" })` when the briefing says "removing X detaches, never cascades" (categoria desativada never deletes documents).

### `db/migrations/00NN_financeiro.sql` and `00NN_gatilhos-financeiro.sql` (migration, batch)

**Analog:** `db/migrations/0010_abertura-do-espaco.sql` (tables) + `0011_gatilhos-abertura.sql` (triggers)

**Trigger-in-separate-migration pattern** (`0013_gatilhos-comparador.sql` full file):
```sql
drop trigger if exists tocar_atualizado_em_cotacao_categorias on cotacao_categorias;
--> statement-breakpoint
create trigger tocar_atualizado_em_cotacao_categorias
  before update on cotacao_categorias
  for each row execute function tocar_atualizado_em();
--> statement-breakpoint
```
Every new table with `criado_em`/`atualizado_em` needs this trigger wired to the pre-existing `tocar_atualizado_em()` function (from migration 0002) in a dedicated `_gatilhos-financeiro.sql` migration, one `drop trigger if exists` + `create trigger` pair per table, each `--> statement-breakpoint` separated.

**No explicit grants needed** — comment in `0013_gatilhos-comparador.sql` confirms `alter default privileges` from migration 0003 already covers new tables created by the same owner (`amassa_owner` → `amassa_app` gets select/insert/update/delete automatically). Do not add manual `grant` statements.

```typescript
export function formatarReais(centavos: number): string {
  const reais = centavos / 100;
  return new Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' }).format(reais);
}
```
