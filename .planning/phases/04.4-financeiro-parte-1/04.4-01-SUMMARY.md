## Decisions Made

- **Numeração (Tarefa 0):** opção A confirmada pelo dono — ver seção própria acima.
- **`textoVendaLancada` recebe o total já formatado**, não centavos: seguindo a disciplina
  existente de `lib/queimas/textos.ts`/`lib/abertura/textos.ts` ("só import de tipo, nunca de
  valor" — `textos.ts` nunca importa `formato.ts`), o parâmetro do plano descrito como
  `totalCentavos` virou `totalFormatado: string`, montado por quem chama (`page.tsx`) via
  `formatarReais`. Mesmo contrato funcional, nomenclatura ajustada à convenção do projeto.
- **`DialogoValorLivre` sem `aria-label` explícito no `DialogContent`**: o Radix já monta
  `aria-labelledby` para o `DialogTitle` ("Valor livre"), e o `getByLabel` do Playwright casa por
  accessible name de QUALQUER elemento (não só campos de formulário) — com o `aria-label`
  explícito redundante, `getByLabel("Valor")` resolvia dois elementos (o diálogo "Valor livre" E
  o campo "Valor"). Removido o `aria-label` redundante e os dois `getByLabel("Valor")` do e2e
  usam `{ exact: true }` para não colidir com o nome do diálogo.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Ambiguidade de `getByLabel("Valor")` no e2e por colisão de accessible name**
- **Found during:** Tarefa 1 (primeira execução do e2e)
- **Issue:** `page.getByLabel("Valor")` resolvia dois elementos — o `DialogContent` (accessible
  name "Valor livre" via `aria-labelledby` automático do Radix) e o campo "Valor" de verdade —
  porque "Valor livre" contém "Valor" como substring e o Playwright casa por conteúdo, não só em
  campos de formulário.
- **Fix:** Removido o `aria-label` redundante do `DialogContent` (o Radix já fornece um via
  `DialogTitle`); os dois `getByLabel("Valor")` do spec passaram a usar `{ exact: true }`.
- **Files modified:** `components/amassa/financeiro/dialogo-valor-livre.tsx`,
  `tests/e2e/financeiro-tracador.spec.ts`
- **Verification:** `npm run test:e2e -- --grep "financeiro tracador"` (segunda invocação) — 26/26
  passaram, desktop e celular.
- **Committed in:** `8d4e6ce` (parte do commit da Tarefa 1 — o e2e só foi commitado depois de
  verde)

**2. [Rule 3 - Blocking] Comentários com a substring literal "new Date" nos módulos que a
proíbem**
- **Found during:** Tarefa 2 (grep de aceite)
- **Issue:** `documento.ts` e `extrato.ts` tinham comentários EXPLICANDO que o módulo não usa
  `new Date()` — mas o grep de aceite do plano (`grep -n "new Date\|Date.now" ...`) é literal e
  não distingue comentário de código, então a própria explicação fazia o grep "encontrar algo".
- **Fix:** Reescritos os dois comentários para não conter a substring, mantendo o mesmo aviso em
  outras palavras ("sem instanciar data nenhuma").
- **Files modified:** `lib/financeiro/documento.ts`, `lib/financeiro/extrato.ts`
- **Verification:** `grep -n "new Date\|Date.now" lib/financeiro/dinheiro.ts
  lib/financeiro/documento.ts lib/financeiro/extrato.ts lib/financeiro/taxa.ts` não encontra nada.
- **Committed in:** `3a91bd5` (Tarefa 2)
