## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `drizzle-orm/node-postgres` embrulha o erro do `pg` em `.cause`**
- **Found during:** Tarefa 3, primeira execução do e2e "cadastros base"
- **Issue:** `ehViolacaoDeUnicidade`/`ehErroDoGatilhoDeTravamento` checavam `"code" in erro &&
  erro.code === "..."` — o mesmo padrão de `ehViolacaoDeChaveEstrangeira` já usado em
  `lib/financeiro/acoes.ts`/`lib/abertura/acoes.ts`/`lib/cotacoes/acoes.ts`/`lib/queimas/acoes.ts`.
  Só que `drizzle-orm/node-postgres` embrulha TODO erro de query num `DrizzleQueryError`, cujo
  `.code` é `undefined` — o SQLSTATE real do Postgres mora em `erro.cause.code`. O e2e provou isso
  na prática: criar uma categoria com nome duplicado gravava a violação no log do servidor
  (`code: '23505'`) mas a tela nunca mostrava "Já existe uma categoria com esse nome." — caía no
  `FRASE_FALHA_AO_SALVAR` genérico.
- **Fix:** `codigoDoErroPostgres(erro)` olha `erro.code` OU `erro.cause.code`, e
  `ehViolacaoDeUnicidade`/`ehErroDoGatilhoDeTravamento` passaram a usar essa função.
- **Files modified:** `lib/cadastros/acoes.ts`
- **Verification:** `npm run test:e2e -- --grep "cadastros base"` (2ª invocação) — o teste de
  nome repetido passou.
- **Committed in:** `f9fcfcb` (Tarefa 3)
- **Nota para fases futuras:** o MESMO padrão quebrado provavelmente existe em
  `ehViolacaoDeChaveEstrangeira` de `lib/financeiro/acoes.ts`, `lib/abertura/acoes.ts`,
  `lib/cotacoes/acoes.ts` e `lib/queimas/acoes.ts` — nenhum deles foi corrigido aqui (fora do
  escopo desta plano, nenhum dos caminhos que este plano exercita passa por eles). Registrado
  como nota técnica, não como item do `WINDOWS.md` (nenhum teste desta fase os exercita para
  provar a falha).

**2. [Rule 1 - Bug] Clique perdido por hidratação no segundo envio do formulário de Taxa (e2e)**
- **Found during:** Tarefa 3, segunda execução do e2e "cadastros base"
- **Issue:** Depois de `window.location.assign` recarregar `/cadastros?sub=taxas`, o teste
  preenchia "31" e clicava "Salvar taxa" imediatamente — a asserção de valor anterior
  (`toHaveValue("3,5")`) passa só com o HTML da renderização no servidor, antes de o React
  hidratar e anexar o `onSubmit`. O clique seguinte virou submissão NATIVA do `<form>` (sem
  `preventDefault`), navegando de verdade em vez de rodar a Server Action — mesma classe de
  "clique perdido por hidratação" já documentada em `tests/e2e/encomendas-filtros.spec.ts`.
- **Fix:** `await page.waitForLoadState("networkidle")` depois da navegação completa, antes do
  segundo preenchimento/clique.
- **Files modified:** `tests/e2e/cadastros-base.spec.ts`
- **Verification:** `npm run test:e2e -- --grep "cadastros base"` (3ª invocação) — o teste de
  Taxas passou nos dois projetos.
- **Committed in:** `f9fcfcb` (Tarefa 3)

**3. [Rule 1 - Bug] `AbasFinanceiro`/`SubAbasCadastros` estouravam 320px por 3px**
- **Found during:** Tarefa 3, terceira execução do e2e "cadastros base" (teste de 320px)
- **Issue:** `scrollWidth 323 > clientWidth 320` em `/cadastros` (mesmo na sub-aba Catálogo,
  vazia — não era conteúdo da lista de categorias). Diagnóstico por injeção temporária de um
  `page.evaluate` que lista elementos com `right > clientWidth` apontou a pílula
  `cadastros-sub-taxas`: cada pílula é `flex-1` sem `min-w-0`, então o piso de largura mínima do
  flexbox (`min-width: auto`) usa a largura do texto INTEIRO sem quebra — para uma palavra única
  como "Categorias" (sem espaço para quebrar), esse piso é maior que a fatia igual que `flex-1`
  daria a cada uma das 4 pílulas, somando um estouro pequeno o bastante para não ser visível a
  olho nu mas grande o bastante para o teste automatizado de UI-06 pegar.
- **Fix:** `min-w-0` + `break-words` em cada pílula de `SubAbasCadastros` (4 pílulas) E,
  preventivamente, de `AbasFinanceiro` (hoje 3 pílulas, mas os planos 07/09 acrescentam Despesa e
  Mês, chegando às mesmas 5 que reproduziriam o mesmo estouro).
- **Files modified:** `components/amassa/cadastros/sub-abas-cadastros.tsx`,
  `components/amassa/financeiro/abas-financeiro.tsx`
- **Verification:** `npm run test:e2e -- --grep "cadastros base|casca de navegação|acessibilidade"`
  (execução final) — 88/88 passaram, incluindo os dois testes de 320px (`casca.spec.ts` e
  `acessibilidade.spec.ts`, que também cobrem `/financeiro`/`/cadastros`).
- **Committed in:** `f9fcfcb` (Tarefa 3)
