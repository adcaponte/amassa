**`lib/abertura/prazos.ts`.** Módulo puro. O único import permitido é o de `diferencaEmDias` de
`lib/abertura/parcelas.ts` — uma aritmética de calendário só, no módulo inteiro. Nada de React,
nada do cliente do banco, nenhuma leitura de relógio: `hoje` entra por argumento como
`YYYY-MM-DD`, sempre.

- `type Urgencia = { tipo: "feita" } | { tipo: "atrasada"; dias: number } | { tipo: "hoje" } | { tipo: "futura"; dias: number }` — união discriminada, um ramo por linha do protótipo, para o `switch` de quem formata ser exaustivo e um caso novo nunca cair num texto genérico em silêncio.
- `urgenciaDaTarefa(tarefa, hoje): Urgencia` — concluída devolve `feita` **antes** de qualquer comparação de data, como no protótipo.
- `ordenarTarefasDoGrupo(tarefas)`: abertas antes de concluídas, e dentro de cada bloco por `prazoEm` crescente. Compare as datas como string (`localeCompare`), que para `YYYY-MM-DD` é a ordem cronológica exata e não precisa de `Date`. Devolva um vetor novo; não ordene no lugar.
- `agruparTarefasPorGrupo(tarefas)` devolve `{ grupo, tarefas, concluidas, total, atrasadas }[]`, na ordem de `ORDEM_DOS_GRUPOS`, pulando grupo sem tarefa. `atrasadas` conta as não concluídas com prazo anterior a `hoje` — é o número que o cabeçalho grita, e a razão de D-10 existir: agrupar sem ele enterraria o atrasado no meio da lista.
- `contarTarefasAbertasPorItem(tarefas)` devolve um `Map<string, number>` com a contagem de tarefas **não concluídas** por `itemId`, ignorando as de `itemId` nulo. É consumido pela Tarefa 2.

**`lib/abertura/consultas.ts`.**
- `listarGestoresAtivos()` devolve `{ id, nome }[]` de `usuarios` com `ativo = true`, ordenado por `nome`. É a lista que o campo de responsável oferece. **Nunca** um vetor de nomes no código: os quatro nomes do protótipo são simulação declarada no próprio protótipo.
